# Знания: рабочая база CBT-ассистента

Три режима: collect → verify → edit. Протокол в skill `cbt-kb`.

## Структура
- `inbox.jsonl` — сырые записи, статус `не проверено`
- `entries.jsonl` — проверенная база (статус: подтверждено / спорно / устарело)
- `history/` — копии entries.jsonl перед каждой правкой
- `../knowledge_base/*.md` — RAG-индексируемые файлы (только топ-уровень)

## Поток
1. **Collect**: новый факт → атомарная запись в inbox.jsonl, статус `не проверено`
2. **Verify**: веб-поиск + сверка с knowledge_base/*.md → статус и уверенность → запись в entries.jsonl
3. **Edit**: правка → сначала копия в history/, потом правка
4. **Publish**: проверенные записи дописываются в `knowledge_base/kb_verified.md` → RAG переиндексирует автоматически

## Формат записи (JSONL)
```json
{"id": "kb-0001", "fact": "...", "source": "...", "date": "2026-09-03", "confidence": "низкая|средняя|высокая", "status": "не проверено|подтверждено|спорно|устарело", "topic": "...", "links": [], "note": ""}
```

## Правила
- Нет источника → confidence не выше `средняя`, source: `не указан`
- Верификатор главнее: его вердикт перебивает collect
- Молча не удалять: правка = новая запись + старая в history/
- Один факт = одна запись, не сливать разное
